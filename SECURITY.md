# Sicherheitsrichtlinie

BlueProceedings ISMS verwaltet Informationen über die Sicherheit von Institutionen. Hinweise auf Schwachstellen nehmen wir
deshalb besonders ernst.

## Schwachstelle melden

Bitte **kein öffentliches Issue und keine Diskussion** anlegen. Stattdessen:

1. bevorzugt über **Security → Report a vulnerability** in diesem Repository (private Meldung an GitHub), oder
2. per E-Mail an [security@blueproceedings.de](mailto:security@blueproceedings.de?subject=Sicherheit%20BlueProceedings%20ISMS) mit dem
   Betreff „Sicherheit BlueProceedings ISMS“.

Hilfreich sind: betroffene Version, Schritte zum Nachvollziehen, erwartetes und tatsächliches Verhalten und deine
Einschätzung der Auswirkung. Bitte keine echten Daten deiner Institution mitschicken.

## Was du von uns erwarten kannst

- Eingangsbestätigung innerhalb von fünf Werktagen.
- Eine erste Einschätzung und, falls nötig, ein abgestimmter Zeitplan für Behebung und Veröffentlichung.
- Nennung in den Versionshinweisen, wenn du das möchtest.

BlueProceedings ISMS wird derzeit von einer Person entwickelt. Wir antworten so schnell wie möglich, können aber keine
Reaktionszeiten wie ein Bereitschaftsdienst zusagen.

## Unterstützte Versionen

Bis zur ersten Version (geplant Januar 2027) gibt es keine veröffentlichte Version. Danach erhält die jeweils
neueste Version Sicherheitskorrekturen; diese Tabelle wird mit der ersten Version ergänzt.

## Bitte nicht

- Systeme Dritter oder fremde Installationen testen.
- Daten anderer Personen abrufen, verändern oder löschen.
- Angriffe auf Verfügbarkeit (Last- oder Denial-of-Service-Tests).
